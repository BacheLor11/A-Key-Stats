# A-Key-Stats

按键与妙控板热力图。每天敲了哪些键、手指在板子上磨出什么形状，一屏看完。

- **不记录你打了什么**：只累计「每颗键被按了多少次」，不存按键顺序、不存字符、不存窗口标题。
- **数据全在本地**：`~/Library/Application Support/A-Key-Stats/`，没有网络请求、没有账号、没有上报。
- **界面**：askb.app 那套排版（宋体标题 / 米白底 / 墨蓝与赭石），支持深色模式。

---

## 采集方式

| 部分 | 技术 | 权限 |
|---|---|---|
| 键盘按键 | `IOHIDManager` 读物理键（usage page 0x07） | 需要「输入监控」 |
| 鼠标点击 / 滚轮 | `IOHIDManager` 按钮元素 + `NSEvent` 滚轮 | 同上 |
| 触控板 / 鼠标表面 | `MultitouchSupport.framework`（私有，`dlopen` 动态取符号） | 不需要 |

`MultitouchSupport` 给的接触点带归一化坐标、速度、接触面积、椭圆长短轴。
`MTDeviceGetDeviceID` 拿到的就是 ioreg 里 `AppleMultitouchDevice` 的 `LocationID`，
用它把设备区分成 **触控板 / 鼠标 / 内建触控板** —— Magic Mouse 上表面也是电容面，会上报接触点，
不区分就会把鼠标的数据算进触控板。

触控板归一化坐标的原点在**左下**，UI 画布原点在左上，所以默认翻转 Y 轴；
如果热力图上下颠倒，去「设置 → 翻转 Y 轴」切一下。

## 数据

```
~/Library/Application Support/A-Key-Stats/
├── days/2026-10-27.json      # 每日聚合：每键次数、24 小时分布、点击、热力网格、里程
└── traj/2026-10-27.pad.bin   # 触控板原始轨迹（降采样，10 字节/点，带手指 id）
    traj/2026-10-27.mouse.bin # 鼠标表面轨迹
```

- 热力网格：32 × 24 格，每格记「停留帧数」≈ 停留时间。
- 轨迹降采样规则：位移 < 0.002 且间隔 < 0.05s 的点丢掉，一周下来几 MB。
- 轨迹格式：`AKST` + 版本(2B) + 保留(2B) 头，之后每点
  `Float32 t(当天秒数) + UInt16 x + UInt16 y + UInt16 手指 id`（v2，10 字节）。
  旧 v1 文件（8 字节，无 id）会原地升级，不会丢数据。
  手指 id 是必需的：双指滚动时两根手指逐帧交替上报，不分段画就会连成一整片 Z 字。
- 滚动口径：触控板双指滚动记作 **触控滚动**（`padScroll`），鼠标（含妙控鼠标表面）的滚动计入 **滚轮**（`scroll`）。
  判定靠 `NSEvent.phase`（连续手势）+ 最近 0.3 秒内哪台设备有接触点，一次手势内的惯性滚动沿用同一归属。

想清空：设置页「清空全部数据」，或直接删掉上面这个目录。

## 色阶怎么读

所有热力图共用一套颜色：米白 → 墨蓝 → 赭石。但映射**不是线性的** ——
`f = pow(value / peak, gamma)`，键盘的 `gamma` 是 0.45、接触面是 0.5（接触面还取 95 分位当 `peak`，
免得一个疯掉的格子把整张图压平）。幂次压缩是为了让低频键也能看出深浅，代价是「深浅」和「次数」不成正比。

所以每张图下方都有一条带刻度的色阶条：

| 位置 | 含义 |
|---|---|
| 左端 `0` | 一次都没按过 / 没碰过 |
| 中间那个数（条上有一条细线的位置） | 墨蓝开始转赭石的临界值 |
| 右端 | 当前峰值（键盘是次数，接触面是帧） |

**峰值会跟着周期变**：同一张图，在「今天」和「全部」里，同一个墨蓝代表的绝对量完全不同。
要比较两个周期，看刻度，别只看颜色。

## 外设信号：这块硬件是不是有毛病

键盘连击、鼠标跳、触控板断报点 —— 这些和「用了多少」无关，是**输入本身可不可靠**。
这一层平时**没有任何入口**：侧栏没有、设置里也没有开关。只有证据攒够，才会在
键盘 / 触控板 / 鼠标页顶部出现一张提示卡。

| 外设 | 指标 | 判定方式 |
| --- | --- | --- |
| 键盘 | 重复触发 | 同一颗键 **70ms 内**被按下两次（人手极限之外） |
| 键盘 | 立刻回删 / 连删重打 | 打字后 300ms 内回删、连续回删 ≥2 次后重新输入；只作参照 |
| 键盘 | 卡键 | 非修饰键按住超过 8 秒 |
| 鼠标 | 跳点 | **孤立尖峰**：前一帧和后一帧都小，只有这一次位移极大（> 中位数 8 倍且 > 60 点） |
| 鼠标 | 断流 | 连续移动中出现 120–600ms 的空档，然后又接着动 |
| 鼠标 | 连击抖动 | 同一键 45ms 内按下两次 |
| 触控板 | 单帧跳变 | 前后帧正常、中间一帧跨过板面 15% 以上 |
| 触控板 | 报点中断 | 手指还在板上，帧间隔 120ms 以上 |

几个刻意的取舍：

- **跳点必须「孤立」**。快速甩鼠标时是一串连续的大位移；传感器出问题是一次跳完就恢复。
  用「中位数 × 倍数 + 前后帧都小」两个条件，才不会把正常快划当成故障。
- **键盘只看重复触发**。「打了字又立刻删」在正常打字里太常见，单独不足以说明问题。
- **判定门槛分两层**：先看 7 天累计样本（键盘 ≥500、鼠标 ≥3000、触控板 ≥3000），
  再要求「经常」—— 重复触发要出现在 ≥2 天，或者单日就到两倍门槛。
- **只存计数**：`days/*.json` 的 `hardware` 段里只有样本数和各指标次数，
  没有按键内容，也没有光标位置。

想直接看原始数字（没有提示卡的时候也能看）：

```bash
./.build/release/AKeyStats --hw 14    # 每台设备的样本数 / 各指标次数 / 离门槛差多少
./.build/release/AKeyStats --ptr 8    # 鼠标位移报文到底有没有从 IOHID 出来（检测的前提）
```

`--ptr` 不是可选项的调试工具：有些鼠标在系统里只报按键、位移走蓝牙私有通道，
那种设备拿不到位移数据，跳点检测对它无效 —— 这条命令就是用来先确认前提的。

## 导出轨迹

触控板页右上角「导出轨迹」，下拉里两组：**导出回放视频** / **导成 CSV**。

### 回放视频（MP4）

「导出回放视频…」选一天导出 MP4。画面就是触控板页那块组件本身 ——
32×24 的热力底图、按 finger 分段的轨迹逐点长出来，和点「回放」看到的一致，
不额外加标题、时钟、水印。

| 项 | 说明 |
|---|---|
| 范围 | 只能按天。轨迹点的 `t` 是「当天 0 点起的秒数」，跨天拼起来没有意义 |
| 时长 | 默认跟回放同一套规则：跨度 ÷ 8，最短 1.2 秒、最长 12 秒；也可手动选 15 / 30 / 60 秒 |
| 尺寸 | 1600 × 1150（触控板 16 : 11.5 的比例），H.264，8 Mbps |
| 配色 | 跟随应用当前深浅色 |

推进是按**点位索引均匀**走的，不是按真实时间 —— 一天的活动可能横跨十几小时，
按真实时间放会有一大半画面是静止的。这一点和 App 里的回放完全一致。

渲染在后台线程逐帧进行，触控板页头部会显示进度；4.7 万个点大约 7 秒渲完。

### CSV

范围可选 今天 / 最近 7 天 / 全部历史：

| 列 | 含义 |
|---|---|
| `date` | 日期（`yyyy-MM-dd`） |
| `time` | 当天时钟 `HH:MM:SS.mmm` |
| `t` | 当天 0 点起的秒数（浮点，用于精确排序） |
| `x` / `y` | 0–1 归一化坐标，已按设置里的 Y 翻转处理 |
| `finger` | 接触点 id：同一次触摸内不变，抬手指换一个。画折线时要按它分段，否则双指滚动会被连成 Z 字 |

导出前会先把采集缓冲 flush 到盘上，不会少最后几秒。写文件是流式的（分块解码 + 攒够 256KB 落盘），
全部历史几百万个点也不会把内存吃满。空白天不会出现在导出里 —— 只有表头反而会让人以为数据丢了。

## 页面

概览（可按需隐藏触控板/鼠标卡片）· 键盘热力（四套配列）· 触控板（热力 + 轨迹回放 + 导出 CSV）
· 鼠标（表面热力 + 点击）· **检测**（按键响应 / 连键 / 鼠标按键）· 历史 · 设置。

概览页顶部有 **今天 / 本月 / 今年 / 全部** 四个周期，条上直接给出各周期的按键总数和天数，
点一下整页（KPI、三张热力图、24 小时分布、按键排行）都跟着切。
跨周期是把逐日统计相加：次数相加、热力网格逐格相加、接触面积取峰值。
「全部」的抬头会写出数据覆盖的日期范围，右侧指标给出日均和累计天数。

「检测」页只做物理层面的体检，不写进任何统计：
手扫一遍键盘，**按过的键会一直亮着**（赭石淡填充 + 描边），正按住的键画成实心，
顶部显示「已覆盖 42/77」和还没按到的键名 —— 全部亮满就说明没有哑键。
另外统计按住时长、同键两次的间隔、鼠标左右中键、双击与连点，
并在同一颗键 50ms 内自己又触发时标红 —— 机械轴触点氧化的典型症状。

## 构建

```bash
./Scripts/build.sh              # 出 build/A-Key-Stats.app
./Scripts/build.sh --install    # 装到 ~/Applications
./Scripts/build.sh --release    # 额外打 zip
```

签名：默认取钥匙串里第一张未吊销的 Apple Development 证书（用 SHA-1，避免同名证书歧义）。
**用固定证书签名很重要** —— 输入监控授权绑定签名身份，ad-hoc 签名每次重建都会掉授权。
可用 `CODESIGN_ID=<sha1或名字>` 指定。

### 键盘不记数时按这个顺序查

1. **完全退出 app 再打开**（⌘Q，不是关窗口）。授权是进程启动时判定的，开关是在 app 运行中
   才打开的话，必须换一个进程才生效。
2. 看顶部提示条。写着「没给到 A-Key-Stats」就点 **重置授权**：它执行
   `tccutil reset ListenEvent com.aibao.AKeyStats` 清掉旧记录，然后重启 app 重新授权。
3. 还是不行就看设置页「采集 → 签名身份」那一行：
   - `ad-hoc（无证书）` —— 每次重装/重编都要重新授权。在目标机器上装好开发者证书，
     `./Scripts/build.sh --install` 会自动挑证书签名。
   - `· 临时目录` —— 系统把 app 挪到 AppTranslocation 下跑了（从「下载」里直接双击启动），
     拖进「应用程序」文件夹再打开。
   - `· 另有副本` —— 机器上还有一份同名 app，列表里那条授权可能属于它。
4. 一条命令拿到全部信息：

   ```bash
   ~/Applications/A-Key-Stats.app/Contents/MacOS/AKeyStats --keyperm 8
   ```

   打印签名身份、输入监控状态、可见键盘、监听 8 秒收到的按键数。

## 开发自检

```bash
./.build/release/AKeyStats --selftest                 # 权限 / 设备识别 / 数据目录
./.build/release/AKeyStats --keyperm 8                # 签名身份 + 权限 + 设备 + 8 秒内的按键数
AKS_DEMO=1 ./.build/release/AKeyStats --snapshot a.png dashboard   # 离屏渲染（假数据）
AKS_DEMO=1 AKS_KEY=noaccess ./.build/release/AKeyStats --snapshot k.png dashboard  # 对键盘提示条版式
AKS_DEMO=1 AKS_HW=mouse ./.build/release/AKeyStats --snapshot m.png mouse          # 对外设提示卡版式
./.build/release/AKeyStats --hwtest                   # 判定器合成事件自测
./.build/release/AKeyStats --hw 14                    # 外设信号的原始计数与判定
./.build/release/AKeyStats --snapshot b.png keyboard  # 离屏渲染（真实数据）
AKS_LAYOUT=ansiFull ./.build/release/AKeyStats --snapshot c.png keyboard  # 指定配列
AKS_DARK=1 ./.build/release/AKeyStats --snapshot d.png dashboard          # 深色
```

## A-Kit 接入

走 L1 状态协议（`Sources/Vendor/AKitStatusKit.swift`，与 A-Sweep 同一套）：

- `bundleId` = `com.aibao.AKeyStats`，`akit.json` 的 `id` = `a-key-stats`
- 菜单项：打开 / 键盘热力 / 触控板 / 鼠标 / 暂停记录 / 设置
- Hub 接管时自己收起菜单栏图标，Hub 掉线 5 秒内自己回来

## 已知限制

1. **ISO 配列的回车画成普通高度**：竖条回车会和工作区的右 shift 抢位置，暂不画 L 形。
2. **接触面积 ≠ 力度**：`size` 是电容接触面大小，真 Force Touch 压力要 `NSEvent.pressure`，
   而且只在按下/拖动时才有值。
3. **私有框架风险**：`MultitouchSupport` 是系统私有组件，macOS 大版本更新可能改符号。
4. **外设信号是统计推断，不是诊断**：门槛按「每千次样本」定，能提示「这块设备的行为和正常输入不一样」，
   但分不清是硬件、驱动、干扰还是习惯。要坐实得换线/换口/换机对比。
5. **鼠标位移依赖 IOHID 的 X/Y 元素**：用 `--ptr` 确认过才有数据；
   少数鼠标（尤其蓝牙私有通道的）只报按键不报位移，那种设备只能看连击抖动。
   取不到符号时只会「不支持」，不会崩。
4. **计数口径**：按住不放只记 1 次（IOHID 侧做了按下状态去重），修饰键也计入。
   同一颗键 35ms 内的重复上报会被挡掉（不计入统计，但在「检测」页计为异常），
   人手物理上做不到 35ms 内连按两次同一颗键。
5. **图标**：`Resources/AppIcon.icns` 由 `Scripts/IconMaker.swift` 生成 —— 原图裁成
   824×824 内容区 + 圆角遮罩 + 透明边，符合 macOS 图标网格。
